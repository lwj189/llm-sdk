### 3.3 三个最容易混的语义（写进注释）

1. **401 是 perform 成功**：curl 只认传输层，HTTP 4xx 照样 `CURLE_OK`。错误体在 `body_out` 里，交给上层 `parseErrorBody`。
2. **取消要判三个条件**：`CURLE_ABORTED_BY_CALLBACK`（进度回调返回 1）或 `CURLE_WRITE_ERROR`（写回调返回 0）+ `cancel.cancelled() == true` → `err.cancelled = true`。
3. **err 文本**：`curl_easy_strerror(code)` + `" (CURLcode N)"`，不要自己编故事；`http_status` 无论成败都取一次 `CURLINFO_RESPONSE_CODE`。

### 4.2 算法（行扫描 + 挂起状态）

- 私有状态：`buf_` + 当前事件的 `event/id/data` + 一个「有没有任何字段」的标志
- `feed`：在 `buf_` 里找 `\n`；切出行 → 去掉行尾 `\r` → 解析 → 从 `buf_` 删掉已消费部分
- **跨块 CRLF**：如果缓冲区最后一个字节是 `\r` 而后面还没来 `\n`，就停在这里等下一块（逐字节重放能过的关键）
- 行以 `:` 开头 → 注释（心跳），跳过，**不产生事件也不清空当前事件**
- 空行 → 当前事件有任何字段就发射并清空；否则跳过
- 字段 `data:` → 剥**一个**前导空格；多行 data 用 `\n` 拼接；`event:`/`id:` 取第一行
- `finish()`：把残留缓冲当最后一行处理，然后有数据就发射；**第二次调用必须返回空**（幂等）
- 不认识的行（`retry:` 等）忽略
### 4.3 四个用例（CHECK + std::cerr，失败打印 用例号/期望/实际）

| # | 输入 | 断言 |
| --- | --- | --- |
| 1 | 整读夹具，一次 feed | 事件数 > 0；首条 data 能喂进 nlohmann 解析；最后一条 data == `[DONE]` |
| 2 | 每个字节单独 feed 一次 | 事件序列与用例 1 **逐字段完全相等**（event/id/data） |
| 3 | 手写混合输入 | CRLF + `: comment` + 多行 data + `data:` 后无空格 → data 拼接正确、注释被跳过 |
| 4 | 末尾无空行 | `finish()` 吐出 1 个事件；再调一次返回空 |

> 实现备注：测试用自定义 `CHECK` / `CHECK_STR` / `CHECK_SIZE`，不用 `assert`——Release 的 `NDEBUG` 会把 `assert` 编掉，测试会假过；自定义宏失败时打印用例号、期望/实际并让 `main` 返回 1。

夹具路径用 `__FILE__` 定位（`__FILE__` 所在目录 + `/fixtures/deepseek_stream.sse`），不依赖 ctest 的工作目录。

### 5.3 chatStream 的两个关键点

1. **`[DONE]` 早停要当成成功**：sink 里见到 `isDoneMark()` 就返回 false 结束传输 → curl 报 `CURLE_WRITE_ERROR` → 主流程若 `done_seen == true`，按成功返回。否则每次正常对话都会变成"错误"。
2. **HTTP 4xx/5xx 的错误体不是 SSE**：sink 里同时把原始字节攒进一个 `raw` 缓冲（流本身只有几 KB），perform 结束后状态码 ≥ 300 就用 `parseErrorBody(raw)` 填 err。
